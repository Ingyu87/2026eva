# 2026-10-14 웹앱 검토 및 개선

학교 문항 편집부터 저장 상태 확인, 파일 다운로드까지 사용자가 만나는 오류와 출력 서식을 점검했다. 학교 실제 문항·응답·다른 부장들의 작업 자료는 변경하지 않았다.

| 확인된 문제 | 반영한 변경 |
|---|---|
| 최초 초안 조회가 실패해도 ‘불러오는 중’ 화면만 표시 | 실패 이유와 다시 불러오기·로그인 이동 버튼 제공 |
| DOCX·HWPX를 전체 대상으로만 다운로드 | 현재 탭을 기본으로 대상별·전체 선택, 대상별 문항 수와 파일명 표시 |
| 다운로드 API 오류가 작업 화면을 대신 표시할 수 있음 | 파일 요청 후 정상 응답만 다운로드, 오류는 창 안에 표시하고 재시도 가능 |
| 빈 대상의 문서를 생성할 수 있음 | 화면과 API에서 차단, 잘못된 대상도 전체로 바꾸지 않고 400 반환 |
| DOCX 안내문의 줄바꿈이 한글에서 사라지고 여러 대상이 같은 쪽에 이어짐 | 명시적인 줄바꿈·대상별 새 쪽 적용 |
| 선택 개수가 지정된 문항에도 ‘모두 고르세요’ 문구 추가 | 문항 본문의 선택 개수 유지, 일괄 안내 제거 |
| DOCX 응답의 캐시 방지 설정 누락 | DOCX·HWPX 모두 private, no-store 적용 |
| 설치된 패키지의 보안 수정 누락 | Next.js 15.5.27, sharp 0.35.5, @fastify/busboy 3.2.3, source-map-js 1.2.2로 잠금 파일 갱신 |

## 확인

- `npm run verify`: 기존 문항·계산·저장·결과 제출 검사와 신규 `verify:export`, `verify:hwpx`를 포함한다.
- `verify:export`: 두 형식의 대상별 출력·삭제 문항 제외·인증·빈 대상·잘못된 대상·서버 실패·캐시 방지, 다운로드 오류 및 파일명 처리 확인.
- `verify:hwpx`: HWPX 패키지·응답 유형 6종·XML·줄바꿈·표 구조 확인.
- 중립적인 교원·학부모 예시 문서를 한글에서 DOCX·HWPX 각각 열고 PDF로 출력했다. 각 4쪽에서 줄바꿈·새 쪽·번호·응답 칸·선택 개수 보존을 확인했다.
- React 검토 기준으로 다운로드 중복 요청 방지, 닫을 때 요청 취소, 대화상자 키보드 동작, 오류 및 진행 상태 안내를 점검했다.
- 브라우저 가상 응답 검사에서 초안 조회 실패 후 재시도, 빈 대상 차단, 로그인 만료 후 작업 화면 유지 및 재시도, DOCX·HWPX 다운로드, 미저장 편집 차단, Esc 닫기, 1440×900·1920×1080 화면 범위를 확인했다. 시각 검토에서 대상 선택칸과 상태 글자가 작아 보이는 부분도 조정했다.
- `npm audit fix --ignore-scripts` 후 보고된 취약점은 0건이었다. 이 결과는 의존성 점검 결과이며 앱 전체의 보안을 보증하지 않는다.

## 범위와 남은 확인

- 저장 구조와 충돌 처리 코드는 바꾸지 않았다. 기존 저장 회귀 검사를 실행했으며 실제 학교 데이터에 시험 수정을 보내지 않았다.
- Google Forms는 기존 모의 API 복구 검사를 실행했다. 실제 Google 계정에서 설문을 새로 만드는 검증은 이번 범위에 포함하지 않았다.
- 브라우저 검증은 `BASE_URL=http://127.0.0.1:3101 node scripts/verify-export-browser.mjs`로 재현한다. 모든 API 요청을 가상 응답으로 대체하며 실제 저장소에는 접근하지 않는다.
