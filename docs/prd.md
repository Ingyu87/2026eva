## 1. 지금 무슨 문제가 있나

### 1.1 작업한 내용이 사라진다 (가장 시급)

부장님들이 **"내가 선택한 문항이 자꾸 날아간다"** 고 합니다.
코드를 확인한 결과 실제로 사라지는 게 맞고, 원인은 **여러 명이 같이 쓰는 구조인데 앱이 그걸 전제하지 않았기 때문**입니다.

학교 계정은 하나(학교 이름 + 비밀번호)이고 부장님들이 나눠서 작업합니다.
그런데 누가 저장을 누르면 **자기가 보고 있던 화면 전체를 통째로 서버에 덮어씁니다.**
그 안에는 교원용·학부모용·학생용·직원용이 전부 들어 있습니다.

```
14:00  A부장, 교원용 작업 시작
14:05  B부장, 학부모용 작업 시작
14:10  B부장 저장 → 'B가 14:05에 봤던 교원용'이 같이 전송됨
       → A부장이 10분간 담은 문항이 전부 사라짐
```

A부장이 나중에 저장하면 이번엔 B의 작업이 사라집니다. **서로 상대 작업을 지우는 구조**입니다.
여럿이 나눠 쓸수록 더 자주 터집니다.

여기에 더해, 저장이 실패해도 **되살릴 방법이 전혀 없습니다.**
학교 내부망에서 서버 접속이 막히면 그날 작업이 통째로 날아갑니다.

### 1.2 화면이 불편하다

부장님들 평가는 **"직관적이지 않다"** 입니다. 확인해 보니 이유가 분명합니다.

- **문항 검색 기능이 아예 없습니다.** 800개가 넘는 문항을 드롭다운 3개로만 찾습니다.
  문항 하나 담는 데 최소 4번을 클릭해야 합니다.
- 화면 높이가 **픽셀로 고정**되어 있습니다. 24인치 모니터에서 아래쪽은 텅 비었는데
  정작 작업은 작은 상자 안에서 스크롤하며 합니다.
- 설정 · 안내문 · 문항 고르기가 **세로로 쌓여 있어** 페이지를 계속 오르내려야 합니다.

### 1.3 문항 자료가 2025년판이다

2026학년도에 **세부영역 분류가 개편**되었습니다.
지금 앱에 들어 있는 816개 문항은 전부 **작년 분류**를 달고 있습니다.

영역·세부영역은 법령과 교육청 정책으로 정해져 **학교가 고칠 수 없는 값**입니다
(기본계획 Ⅴ-3-가-2, 가이드북 Q6). 작년 분류로 만든 설문은 **제출 서식에 넣을 수가 없습니다.**

### 1.4 설문까지만 만들고 끝난다

현재 앱은 **설문지를 만드는 데서 끝납니다.**
설문을 돌린 뒤 결과를 정리하고, 분석하고, 제출 서류를 만드는 일은 전부 수작업입니다.
이 부분이 사실 가장 오래 걸리고 가장 어렵습니다.

## 2. 무엇을 만들 것인가

### 2.1 한 줄 요약

> 평가문항 자료를 넣으면 **설문이 만들어지고**,
> 설문 결과를 넣으면 **제출 서류 3종이 만들어지는** 웹앱.

### 2.2 목표

| # | 목표 | 왜 |
|---|---|---|
| G1 | **여러 명이 동시에 작업해도 아무것도 사라지지 않는다** | 지금 매일 데이터가 유실되고 있음 |
| G2 | **한 화면에서 스크롤 없이 문항을 고른다** | 24인치 모니터 환경, 클릭 최소화 |
| G3 | **2026 평가체제를 정확히 따른다** | 안 맞으면 제출 자체가 불가 |
| G4 | **설문 결과를 넣으면 분석 결과가 나온다** | 수작업 중 가장 오래 걸리는 부분 |
| G5 | **제출 서류 3종을 양식 그대로 만든다** | 서식이 어긋나면 반려됨 |

### 2.3 산출물 3종

설문 결과를 넣으면 이 세 가지가 나옵니다.

| 산출물 | 형식 | 용도 | 기준 양식 |
|---|---|---|---|
| **평가지표 및 현황** | XLSX | 교육지원청 제출 | 교육청 배포 템플릿 |
| **설문 결과 보고서** | HTML | 교내 공유, 토론회 자료 | 2025년 가동초 결과 보고서 |
| **학교평가서** | DOCX | 교육지원청 제출, 누리집 탑재 | 가이드북 서식3-1 · 3-2 |

## 3. 누가 쓰나

### 3.1 학교 담당 부장 (주 사용자)

- 학교당 3~6명이 **영역을 나눠 맡습니다.**
- **동시에 접속해 작업합니다.** 이게 기본 전제입니다.
- 컴퓨터를 아주 잘 다루지는 않습니다. 화면에 안 보이면 없는 기능입니다.
- 24인치 모니터, 크롬 브라우저, 학교 내부망(서버 접속이 막히는 경우 있음).
- 9~10월(문항 작성), 11~12월(평가 실시·보고서 작성)에 집중적으로 씁니다.

### 3.2 관리자

- 학교 계정을 만들고 비밀번호를 초기화합니다.
- 문항 자료를 새 학년도 것으로 교체합니다.

## 5. 반드시 지켜야 하는 규정

아래는 **협상 대상이 아닙니다.** 어기면 제출이 반려되거나 잘못된 숫자가 교육청에 갑니다.

| # | 규정 | 근거 |
|---|---|---|
| R1 | 영역·세부영역은 **학교가 수정 불가**. 평가지표·평가문항만 자율 | 기본계획 Ⅴ-3-가-2 / 가이드북 Q6 |
| R2 | 2026 세부영역 개편 반영 (Ⅰ-1·Ⅰ-3·Ⅲ-1 명칭 변경, Ⅲ-2+Ⅲ-3 통합) | 가이드북 Q1 |
| R3 | 설문은 **5단계 척도**, 학교평가서는 **4단계 척도**로 환산 | 가이드북 p.9 / p.51 |
| R4 | 영역 평균은 **문항 평균의 평균이 아님.** 영역 전체 응답 기준 가중평균 | 가이드북 p.51 |
| R5 | 4단계 기준: 4.0↑ 매우우수 / 3.0~4.0 우수 / 2.0~3.0 보통 / 2.0↓ 미흡 | 가이드북 p.51 |
| R6 | 학생·학부모·교원은 **Ⅰ·Ⅱ·Ⅲ 전 영역 필수**. 직원만 일부 가능 | 가이드북 Q9 |
| R7 | **문항별 점수는 학교 자체 보관.** 영역별 평균만 제출 | 가이드북 p.51 / p.60 |
| R8 | 1학기는 **중간평가**. 학교평가서에는 **학년말 결과만** 반영 | 가이드북 Q12 |
| R9 | 엑셀 템플릿은 셀 서식·병합·시트명 변경 금지. 배경색 있는 칸만 입력 | 템플릿 A2 경고문 |

### R8 때문에 필요한 것: 모드 분리

앱 이름이 "1학기"인데 학교평가서를 뽑으면 규정 위반입니다.
**두 가지 모드**로 나눕니다.

| 모드 | 시기 | 나오는 것 |
|---|---|---|
| 중간평가 | 7월 | 설문지, 구글폼, 결과 보고서(HTML) |
| 학년말 학교평가 | 11~12월 | 위 전부 **＋ 평가지표 및 현황(XLSX) ＋ 학교평가서(DOCX)** |

제출용 서류는 학년말 모드에서만 만들 수 있게 합니다.

## 6. AI(Gemini)는 무슨 일을 하나

**계산은 프로그램이, 해석은 AI가 합니다.**

| 일 | 담당 | 이유 |
|---|---|---|
| 평균 점수 계산, 4단계 판정 | **프로그램** | 보고서에 4.92라고 적힌 숫자는 **반드시 4.92여야** 합니다. AI에게 산수를 맡기면 안 됩니다 |
| 격차 찾기, 원인 분석, 개선방안, 종합의견 | **AI** | 여기가 보고서의 실질입니다 |

### AI가 해야 하는 분석 수준

"어느 항목이 높았다" 정도로는 보고서가 되지 않습니다. 아래 수준을 요구합니다.

1. **주체 간 인식 격차 해석**
   예) 예산 투명성: 교원 4.92 vs 학부모 4.08
   → *사업이 부실한 게 아니라 **공개와 안내가 부족**한 것*

2. **학년별 추세 읽기**
   예) 독서·인문교육 4학년 4.25 → 5학년 4.02 → 6학년 3.97
   → *고학년 프로그램 재설계 필요*

3. **상대적 저점 찾기**
   전 항목이 4점대여도, 그 안에서 가장 낮은 곳을 짚어냅니다

4. **숫자와 글의 교차 확인**
   급식 점수 최저 **＋** 서술형에서 급식 언급 30% 이상 → **최우선 과제로 승격**
   점수는 낮은데 서술형 언급이 없으면 → 우선순위 하향

5. **서술형 의견 묶어내기**
   흩어진 자유 응답을 주제별로 묶고, 빈도와 강도를 함께 제시

6. **작년 과제가 지켜졌는지 확인**
   작년 '향후 추진계획' 항목의 점수가 올랐는지 대조 → 환류가 작동했는지 평가

7. **원인 → 개선방안 → 교육계획 반영**
   가이드북 37쪽이 제시한 4단 구조 그대로 생성

### AI가 지어낸 숫자를 막는 장치

AI가 쓴 모든 문장에 **근거(문항 번호 + 점수)를 같이 달게** 합니다.
프로그램이 그 숫자가 실제 계산 결과에 있는지 대조하고, 없으면 그 항목은 다시 씁니다.

## 7. 완성 판단 기준

아래가 전부 되면 v2 완료입니다.

### 7.1 작업이 사라지지 않는다 (G1)

- [ ] 브라우저 2개로 같은 계정 로그인 → **다른 대상**을 각각 편집·저장 → **양쪽 다 남는다**
- [ ] 같은 대상의 **다른 문항**을 편집 → 양쪽 다 남고, 3초 안에 서로의 변경이 화면에 보인다
- [ ] **같은 문항**을 동시 편집 → 나중 저장자에게 안내가 뜨고 선택지를 준다. **말없이 덮어쓰지 않는다**
- [ ] 순서를 바꾸는 동안 다른 사람이 문항을 추가해도 양쪽 다 유지된다
- [ ] 인터넷을 끊고 문항 10개를 담은 뒤 새로고침 → 재접속 시 자동 복구된다
- [ ] 저장 안 된 상태로 탭을 닫으려 하면 경고가 뜬다
- [ ] 화면 위쪽에 저장 상태와 동시 접속자가 항상 보인다

### 7.2 화면이 편하다 (G2)

- [ ] 1920×1080에서 **페이지 세로 스크롤이 없다**
- [ ] 문항 1개 담기 = **검색어 입력 + 클릭 1번** 이내
- [ ] 대상 4개를 바꿔도 검색어와 트리 위치가 유지된다
- [ ] `design.md`의 색·간격 규칙을 벗어난 값이 없다

### 7.3 규정을 지킨다 (G3)

- [ ] 문항 풀이 2026 세부영역 체계다
- [ ] 학생·학부모·교원에게 비어 있는 영역이 있으면 경고가 뜬다
- [ ] 중간평가 모드에서는 제출 서류 버튼이 잠겨 있다

### 7.4 결과가 분석된다 (G4)

- [ ] 설문 결과 파일을 올리면 문항별·영역별 평균과 4단계 판정이 나온다
- [ ] **가이드북 51쪽 예시를 넣으면 4.4점 / 매우 우수가 그대로 나온다** ← 계산 검증
- [ ] "매우 그렇다"가 5점으로 계산된다 (뒤집히지 않는다)
- [ ] AI 분석 결과에 근거 숫자가 달려 있고, 지어낸 숫자가 없다

### 7.5 서류가 나온다 (G5)

- [ ] 엑셀: 템플릿 서식이 그대로 유지된 채 값만 채워진다
- [ ] HTML: 탭 3개, 학생 점수가 학년별로 나뉜다
- [ ] DOCX: 가이드북 서식3-1 · 3-2 구조와 일치한다
- [ ] 제출용 파일과 교내 보관용 파일이 분리된다 (R7)

## 8. 필요한 서식 자료 — 이미 다 있습니다

> **결론: 지금 있는 자료만으로 전부 만들 수 있습니다. 별도 요청이 필요 없습니다.**

| # | 서식 | 지금 상태 |
|---|---|---|
| 1 | **학교평가서 (서식3-1 · 3-2)** | ✅ **가이드북 60~61쪽에 구조 전부 있음** |
| 2 | **평가지표 및 현황 엑셀** | 🟡 2025판 보유 → 2026판이 오면 **파일만 교체** |

**1번**: 학교평가서는 학교가 작성해 제출하는 문서입니다. 빈 서식 파일을 받아야 하는 게 아니라
**구조만 맞으면 됩니다.** 가이드북에 표 구조·열 이름·주석까지 다 나와 있습니다.

**2번**: 2025 템플릿으로 개발하되, 산출물 생성기를 **템플릿 자동 인식 방식**으로 만듭니다.
셀 주소를 코드에 박지 않고, 템플릿을 읽어 세부영역·평가지표·주체 열의 위치를 스스로 찾습니다.
2026 파일이 오면 **파일만 갈아 끼우면 끝**이고 코드는 손대지 않습니다.

> ⚠️ 2026에서 Ⅲ-2와 Ⅲ-3이 통합되므로 엑셀의 **행 번호는 확실히 밀립니다.**
> 셀 주소를 하드코딩하면 2026 템플릿이 왔을 때 전부 다시 짜야 합니다.
> 자세한 방식은 `implementation.md` 0단계.
