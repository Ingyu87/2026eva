## 1. 전체 그림

전체를 **9단계**로 나눕니다. 단계마다 그것만으로도 쓸모가 있게 쪼갰습니다.
중간에 멈춰도 거기까지는 실제로 쓸 수 있습니다.

```
0단계  템플릿 준비          ← 지금 있는 자료로 진행 가능
  │
1단계  작업 유실 해결        ← 최우선. 지금도 매일 데이터가 사라지는 중
  │
2단계  화면 재설계           ← 1과 병행 (저장 상태 표시가 맞물림)
  │
3단계  2026 문항 전환
  │
4단계  모드 분리
  │
5단계  구글폼 확장
  │
6단계  계산 엔진             ← 여기부터 '결과 분석' 영역
  │
7단계  AI 해석
  │
8단계  산출물 3종
```

### 왜 이 순서인가

| 순서 | 이유 |
|---|---|
| 0을 먼저 | 8단계에서 쓸 템플릿 인식 방식을 먼저 정해야 함. 자료 요청은 불필요 |
| 1이 최우선 | **현재 운영 중이고 데이터가 계속 유실되고 있습니다.** 다른 어떤 기능보다 급함 |
| 2를 1과 같이 | 저장 상태 표시(`✔ 저장됨`)가 1단계 결과물이자 2단계 화면의 일부. 따로 하면 두 번 만듦 |
| 3이 4보다 먼저 | 문항 데이터가 바뀌면 모드 분리 로직도 영향받음 |
| 5가 6보다 먼저 | 학년 문항이 설문에 없으면 학년별 집계 자체가 불가능 |
| 6이 7보다 먼저 | AI는 계산된 숫자를 입력으로 받음 |

### 0단계 — 템플릿 준비

> **결론: 지금 있는 자료만으로 8단계까지 전부 만들 수 있습니다.**
> 2026 템플릿은 나중에 **파일만 갈아 끼우면** 됩니다. 코드는 고치지 않습니다.

#### 자료 현황

| # | 필요한 것 | 지금 상태 | 판단 |
|---|---|---|---|
| 1 | 학교평가서 서식3-1 · 3-2 | **가이드북 60~61쪽에 구조 전부 있음** | ✅ **요청 불필요** |
| 2 | 평가지표 및 현황 엑셀 템플릿 | 2025판 보유. 2026판 미확보 | 🟡 2025판으로 개발 → 나중에 교체 |

**1번은 별도 자료가 필요 없습니다.**
학교평가서는 학교가 작성해 제출하는 문서라 빈 서식 파일을 받아야 하는 게 아닙니다.
가이드북에 표 구조·열 이름·주석까지 전부 나와 있으므로 그대로 재현하면 됩니다.
(글꼴·여백 같은 세부는 나중에 실제 제출본을 보고 미세조정)

**2번은 2025판으로 개발합니다.** 단, 8-1을 **템플릿 자동 인식 방식**으로 만드는 것이 조건입니다.

#### 템플릿 자동 인식 — 나중에 교체 가능하게 만드는 방법

> ⚠️ **이 방식을 지키지 않으면 2026 템플릿이 와도 코드를 다시 짜야 합니다.**
> 2026에서 Ⅲ-2와 Ⅲ-3이 통합되므로 **행 번호는 확실히 밀립니다.**

❌ **금지 — 셀 주소 하드코딩**
```ts
sheet.getCell("G6").value = studentCount;   // 행이 밀리면 전부 어긋남
```

✅ **필수 — 템플릿을 스캔해 위치를 찾아냄**
```ts
// 1. B열을 훑어 세부영역 행 위치를 찾는다
// 2. C열에서 각 평가지표 이름과 행 번호를 읽는다
// 3. 헤더 행에서 '학생/학부모/교원/직원' 열 번호를 찾는다
// 4. '합계' 행과 '기타' 행을 따로 표시해 둔다
// 5. 그렇게 만든 좌표표에 값을 넣는다
```

**템플릿이 자기 구조를 말해주게** 만드는 것입니다.
2026 파일로 바꿔 넣으면 앱이 알아서 새 위치를 찾습니다.

#### 템플릿 등록 화면 (관리자)

템플릿을 올리면 앱이 인식 결과를 보여주고 확인받습니다.

```
✔ 템플릿 인식 완료
   세부영역 10개  ·  평가지표 47행  ·  주체 열 4개  ·  시트 2개
   [이대로 사용]   [수동으로 맞추기]
```

- 인식 실패 시 수동 연결 화면 제공
- 인식 결과를 `templates/{파일명}.map.json`으로 저장해 재사용

#### 폴더 구조

```
templates/
  indicator-status-2025.xlsx      ← 지금 있는 것. 개발·테스트용
  indicator-status-2026.xlsx      ← 나중에 여기에 넣으면 끝
  indicator-status-2026.map.json  ← 인식 결과 (자동 생성)
```

**끝났다고 보는 기준**
- [ ] 2025 템플릿이 `templates/`에 있다
- [ ] 8-1 코드에 셀 주소가 하드코딩된 곳이 **0곳**이다
- [ ] 템플릿 등록 화면에서 2025 템플릿 인식이 성공한다
- [ ] (템플릿 확보 후) 2026 파일로 교체했을 때 **코드 수정 없이** 동작한다

### 1단계 — 작업 유실 해결 ★최우선

**목표:** 여러 명이 동시에 작업해도 아무것도 사라지지 않는다.

#### 1-1. 데이터 구조 쪼개기

- `surveyDrafts/{id}.itemsByAudience` → `surveyDrafts/{id}/items/{itemId}` 서브컬렉션
- 읽기 시점 자동 변환 (서비스 중단 없음)
- `rev` 필드 추가 (메타 + 각 항목)
- 손대는 파일: `src/lib/store.ts`, `src/lib/types.ts`

#### 1-2. 순서를 분수 인덱스로

- **`normalizeOrder()` 제거** ← 이걸 안 지우면 1단계 전체가 무의미합니다
- `order`를 정수 → 실수로. 삽입 시 앞뒤 값의 중간값 사용
- 화면 번호는 렌더링 때 계산 (저장 안 함)
- 손대는 파일: `src/components/SchoolEvaluationApp.tsx`, `src/lib/store.ts`

#### 1-3. API 재설계

- `PUT /api/draft` **폐기**
- 신규: `PATCH /api/draft/meta`, `POST|PATCH|DELETE /api/draft/items`, `GET /api/draft/sync`, `POST /api/draft/presence`
- 모든 쓰기를 Firestore 트랜잭션 + `expectedRev` 검사로
- 손대는 파일: `app/api/draft/` 전체

#### 1-4. 충돌 안내 UI

- 409 응답 시 선택 대화상자 (덮어쓰기 / 상대 유지 / 비교)
- **자동 덮어쓰기 경로를 코드에서 완전히 제거**

#### 1-5. 로컬 아웃박스

- 편집 → localStorage 큐 기록 → 서버 전송 → OK면 큐에서 제거
- 지수 백오프 재시도, `online` 이벤트 재전송
- 재접속 시 큐 자동 감지·전송
- `beforeunload` 경고

#### 1-6. 실시간 반영 + 접속자 표시

- 3초 폴링 `GET /api/draft/sync?since={서버 타임스탬프}` (`spec.md` 4.5)
- `rev`는 충돌 감지 전용. 동기화 커서로 쓰지 않음
- 삭제는 tombstone(`deleted:true`)으로 남겨 동기화에 잡히게 함
- 탭 비활성이면 15초
- presence heartbeat 동봉
- 내가 편집 중인 항목은 덮어쓰지 않음

#### 1-7. 사용자 표시 이름

- 로그인 직후 1회 질문 → `draftAuthors` 목록에서 선택 또는 직접 입력
- `localStorage`에 저장, 설정 모달에서 변경 가능, 건너뛰면 `사용자 N`
- **인증이 아니라 표시용 라벨.** 권한 판단에 쓰지 않음 (`spec.md` 4.5.1)
- `presence.displayName`, `item.updatedBy`에 기록

#### 1-8. 저장 상태 표시

- 상단바 고정 배지 (`✔ 저장됨` / `↻ 저장 중` / `⚠ 미전송 N건` / `👥 접속자`)

**끝났다고 보는 기준**

서버 동작은 `npm run verify:concurrent` 로 자동 검증합니다 (2026-09-18 기준 20/20 통과).

- [x] 브라우저 2개, 같은 계정, **다른 대상** 편집·저장 → 양쪽 다 남는다. 경고도 안 뜬다

### 3단계 — 2026 문항 전환

#### 3-1. 예시자료 적재 — Upstage 연동

- `1_(초)2026 학교평가 평가문항 예시 자료.pdf` → JSON (963행: 교원 272·학부모 246·학생 217·직원 228)
- **Upstage `extract_information`** 사용 (`spec.md` 4.1의 스키마)
  - 기존 `pdf-parse` 기반 처리를 대체
  - `app/api/recommend/pdf/route.ts` → `app/api/ingest/question-bank/` 로 재작성
- **정규화 필수** (Upstage 결과라도 반드시 거침)
  - 허용 세부영역 10개와 대조, 안 맞으면 확인 대기열로
  - 중점(`·` `･` `・`)·공백·로마숫자 통일
  - 페이지 경계 유령 행 제거 (**확인된 것 4개**)
  - `교원전문성 신장` → `교원 전문성 신장`
- 환경변수 `UPSTAGE_API_KEY` 추가
- 손대는 파일: `scripts/` 신규, `json_export/` 교체, `.env.example`

## 부장 링크와 도움말 그림

**부장 링크(연구부장 ↔ 일반 부장)**
- 연구부장은 학교 계정, 일반 부장은 연구부장이 만든 링크(`/?invite=…`)로 들어옵니다. 초안은 학교당 하나이고 화면과 권한만 갈립니다.
- 부장은 문항 구성만 봅니다. 시기·결과·서류·설정·내보내기·모두 비우기는 화면에서 숨기고 서버에서도 막습니다.
- 부장이 담은 문항에는 `ownerId`(링크 토큰의 해시 일부)와 `ownerLabel`이 붙습니다. 부장은 **자기가 담은 문항만** 수정·삭제·이동할 수 있고(서버 강제), 대상이 정해진 링크는 그 대상 문항만 다룹니다.
- 부장이 **제출**을 누르면 `submittedAt`이 찍히고, 이후 문항을 고치면 지워져 "작성 중"으로 돌아갑니다. 연구부장은 상단 "부장 작업 n/m"과 설정의 부장 작업 탭에서 확인합니다.
- 링크를 끊으면(`revoked`) 이미 들어온 부장도 다음 요청부터 401입니다.

**도움말 그림 / OG 이미지**
- 그림은 손으로 그리지 않고 실제 화면에서 뽑습니다. 화면을 바꾸면 다시 뽑으세요.
  ```bash
  npm run dev                 # 다른 터미널
  npm run guide:capture       # BASE_URL, BROWSER_PATH 환경변수 지원. 로컬 서버(localhost)에서만 실행됩니다.
  ```
- 결과: `public/guide/*.png`(도움말), `public/og-image.png`(기본 미리보기 1200×630), `public/og-invite.png`(부장 링크 미리보기).
- 부장 링크를 카카오톡에 붙이면 링크 전용 문구·이미지가 보입니다(`app/page.tsx`의 `generateMetadata`). 토큰은 미리보기에 싣지 않고 검색 색인도 막습니다.
